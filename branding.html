02
Why We Built This

바이브코딩에는
반복되는 패턴이 있다

AI가 코드를 생성할 때, 보안 컨텍스트 없이 동작 우선으로 작성한다.

그 결과, 수십 개의 AI 생성 코드를 분석하면 같은 취약 패턴이 반복 등장한다. 우연이 아니라 AI의 훈련 데이터와 프롬프트 구조에 기인한다.

bandit은 일반 보안 규칙을 쓴다.
SLAyer는 바이브코딩 출력에 특화된 7가지 패턴을 탐지한다.
V-01

하드코딩 크레덴셜

"일단 예시로" 넣은 API 키가 그대로 배포된다. AI는 교체 알림을 주지 않는다.

V-02

DEBUG = True 배포

개발 예제를 그대로 복붙한 결과. Flask 디버그 모드가 프로덕션에서 실행된다.

V-03

MD5 패스워드 해싱

오래된 튜토리얼 코드가 훈련 데이터에 많다. AI는 MD5를 당연히 쓴다.

V-04

shell=True, f-string SQL, bare except

"편하게 동작하게", "에러 없애줘" 프롬프트의 전형적 결과물. 기존 린터도 맥락을 모른다.
