SL/Ayer

A security scanner for web service code created with AI coding tools.

It finds seven common risks, asks an installed AI CLI to patch them, then checks the code again.

Problem

AI-generated web service code often works before it is safe. Common issues include hardcoded secrets, unsafe commands, weak hashes, and debug mode left on.

01 — Problem Statement

AI code generation is fast.
And it is risky.

Add an API key and connect the external service quickly
API_KEY = "sk-prod-a3f9...c22b" requests.get(url, verify=False) -> Public immediately after GitHub push · exposed to MITM attacks
Real case: exposed API key led to $3,000 in cloud charges in one day
Add user search
query = f"SELECT * FROM users
  WHERE name = '{name}'" -> '; DROP TABLE users; -- in name can delete the whole database
SQL injection — tied to 18% of 2024 data breaches (OWASP A03)
Run it for production quickly
app.run(debug=True, host='0.0.0.0') -> Flask debugger exposed to the internet · remote server code execution possible
Debug mode = remote code execution (RCE) risk
There is an error; just hide it
try:
    process(data)
except:
    pass -> No logs after compromise · anomaly detection blocked
Attack not visible — average breach detection time is 207 days (IBM, 2024)

03 — Methodology

How we define
the ruleset

Existing security tools focus on general developer code. SLAyer analyzes GitHub repositories containing AI-generated code, then selects seven rules with a frequency x impact matrix.

STEP 01
Data collection
CLAUDE.md / AGENTS.md
Collect repositories with these files
Evidence of AI CLI generation
Python + JS/TS
STEP 02
Full analysis
AST + Regex
For each candidate pattern
Count frequency
-> frequency score
STEP 03
Impact matrix
Five-axis scoring
Attack difficulty · impact
Detection confidence
AI amplification factor
STEP 04
Score merge
impact x 0.6
+ normalized frequency x 0.4
14 candidates -> top 7
CWE mapping confirmed
STEP 05
Seven rules confirmed
Deterministic AST detection
Automatic patch feasibility
Final validation
-> SLAyer ruleset
Five impact axes (x0.6)
A. Real-world exploitability x0.25
B. Impact severity x0.25
C. Time-to-Exploit x0.20
D. AST/regex detection confidence x0.15
E. AI code amplification factor x0.15
Final selection formula
Score = impact total x 0.6 + log(frequency) / log(max) x 5 x 0.4
Frequency source: dataset + drepos + repos, three source sets combined · each scored on a 1–5 scale
Compared with bandit: AI-specific ruleset Compared with semgrep: zero setup lines Compared with SonarQube: one pip command Compared with Snyk: no API key
